## Fixes for dev, most important first

1. **No social card on any page (og:image missing).**
   Where: `admin/build/lib/shell.mjs:80-83`, where the head has og:url, og:title, og:description and og:site_name only. There is no `og:image`, `og:type` or `twitter:card`, and no rasterised card exists in `assets/`.
   Pages: 926 of 926.
   Fix: render `design/brand/templates/social-card-1200x630.svg` to a PNG (e.g. `assets/brand/social-card.png`; the template's text uses Newsreader/Plex, so render it with the fonts available, for instance with Playwright at build time or once by hand). Then add `og:image` (absolute URL, from `site.BASE`), `og:image:width` 1200, `og:image:height` 630, `og:image:alt`, `og:type` (`article` for type=article, else `website`) and `<meta name="twitter:card" content="summary_large_image">`. Per-page cards with the title are optional, and are a later step.

2. **Off-palette blue/orange/teal series on the admin charts (the only blue a reader actually sees).**
   Where: `assets/admin/admin.css:14` (`--k-conductor: #1baf7a; --k-desk: #eb6834; --k-builder: #2a78d6`), and the dark versions at `:19` and `:24` (`#199e70`, `#d95926`, `#3987e5`). Used by `:75` (matrix heat `color-mix` on `--k-builder`, so the whole activity matrix is tinted blue), `:92` and `:103`, and drawn by `admin/build/features/admin-draw.mjs:161` and the admin charts.
   Pages: 2 confirmed by markup (`admin/index.html`, `admin/timeline/index.html`). The matrix may also be on other admin pages; 24 pages load admin.css. Confirmed in the computed styles: rgb(42,120,214) light and rgb(57,135,229) dark.
   Fix: map the agent kinds to the brand. Suggested: builder = `var(--brand-green)`, desk = `var(--brand-red)`, conductor = `var(--ink)`, ci = `var(--ink-3)`, with shapes still told apart as they are now (circle/square/diamond). Base the matrix `color-mix` on `--brand`. If the designer wants a separate data-viz palette, it belongs in `assets/tokens.css` and needs a yes from `designer@`.

3. **Footer "Source code" link points to the old repository on every page.**
   Where: `data/site/nav.json:180` (`https://github.com/SGit-AI/SGit-AI__Website__Newsroom__Web-Summit`). `data/site/site.json` `repo` and `git remote` are both `PrompTugal/PrompTugal__News__Website`, and the agent block and llms.txt already use the new one.
   Pages: 926.
   Fix: set it to `https://github.com/PrompTugal/PrompTugal__News__Website`. Better, have the shell/config take it from `site.json` `repo` so the two cannot drift. (GitHub may redirect the old URL; uncertain, not checked.)

4. **Dead cobalt fallback tokens in core.css (not visible today, but the old accent is still in the shipped CSS).**
   Where: `assets/core/core.css:12` (`--brand: #1b4597; --brand-2: #10306d; --brand-soft: #e3e9f5`) and `:21` (dark `#93b1ff; #bccfff; #1a2440; #0b1530`), inside `:where(:root)`. `tokens.css` `:root` outranks them, so the computed colours are the brand's (checked on 10 page types).
   Pages: core.css loads on all 926. If tokens.css ever fails to load, links go cobalt.
   Fix: replace with the brand values (`#006600 / #004d00 / #e2eedf / #ffffff`, dark `#6dbb7e / #9bd3a7 / #16281c / #0b1a0e`), or delete the block. Same for the cobalt `var()` fallbacks in `assets/admin/admin.css:6` and `:64`, `assets/meter/meter.css:28` and `:36`, `assets/vault/vault.css:14` and `assets/graph/explorer.js:23` (`'#1b4597'`, `'#e3e9f5'`). These are fallbacks only, low risk.

5. **Old azulejo mark still shipped and exported.**
   Where: `assets/brand/mark.svg` (cobalt `#1b4597` tile, `<title>PromptUGAL</title>`, publicly served); `admin/build/lib/shell.mjs:24` and `:28-29` (`MARK` export and its comment, unused by any feature); `assets/site.css:59-62` and `:462` (`.mark` rules); `admin/build/README.md:152` still calls mark.svg "our tile, the favicon".
   Pages: 0 render it (no page references it). It is dead code plus a public file with the old name and colour.
   Fix: delete `mark.svg`, the `MARK` export and the `.mark` CSS, and update the README row to list the v2.0 assets.

6. **Type weights outside the brand (Plex Sans 400/600, Plex Mono 400, Newsreader 600 for heads).**
   - Sans 700: `assets/site.css:106, 124, 127, 142, 262, 324, 328, 358, 369, 464, 527, 561, 698, 765`; `assets/search/search.css:26, 37`; `assets/graph/graph.css:18` (all the small uppercase labels, the h2s, kickers and footer heads). Move these to 600.
   - Mono 500: about 30 rules (`site.css` 20, e.g. `:63` the motto; `chat.css` 1, `core.css` 2, `graph.css` 3, `meter.css` 3, `search.css` 1, `vault.css` 1). Use 400, and `plex-mono-500.woff2` can then be dropped from `assets/fonts.css:7`.
   - Mono 600: `site.css` (2 rules), `graph.css:74`, `meter.css` (1). There is no 600 mono face, so the browser fakes the bold. Use 400.
   - Sans 500: 14 in site.css (e.g. `:43` and `:647`, the dateline links), plus a few in the feature CSS. Use 400 or 600.
   Pages: all 926 (site.css). These are visual-nuance issues, not breakage. Confirm with designer@ before the sweep.
   No foreign families were found: only Newsreader, IBM Plex Sans and IBM Plex Mono are used, with system stacks only as fallbacks in `tokens.css:46-48`. The `monospace` in the computed styles is the UA default on `<pre>`, whose `<code>` child is set in Plex Mono.

7. **Dark theme-color does not match the dark page.**
   Where: `admin/build/lib/shell.mjs:89` (`#121317`), while the dark paper in `tokens.css` is `#111214`.
   Pages: 926.
   Fix: use `#111214`, or move the dark paper to `#121317` (brand ink). Cosmetic.
