About PrompTugal.news

Who runs PrompTugal.news, how we make it, and the limits we work within.

ON THIS PAGE

The brief: how PrompTugal.news is meant to work, from Dinis Cruz's own words, is the brief pack.

INDEPENDENT, AND WHO WE ARE

PrompTugal.news: technology and AI, in context, from Portugal for Europe. Its first edition is Web Summit Lisbon 2026. We are not affiliated with Web Summit and do not speak for it: we name it only to say where we report from. We are powered by RiskMandate, which the same team works on, so we are not independent of RiskMandate, and we say so on every page.

OUR RULES
We only publish facts we can source. Each one links to a public page, with the date we read it.
We leave out anything we are unsure of, and say so.
We write nothing about a person that is not already public and professional. We never publish contact details.
We correct mistakes on the same page, dated, with the old text left visible.

Read our disclosure to see what interest we have in what we cover.

HOW WE MAKE IT

We copied the shape of three earlier newsrooms: newsroom.sgit.ai, php.oct.2026.newsroom.sgit.ai and pt.newsroom.sgit.ai. We also follow sgit.ai's guidance for every repository.

Prose is plain text, facts are data. Each article and page of prose is a markdown file. Every fact (each company, event, person, place and topic) is a JSON file in a folder of its own, checked against a schema, and published again as data and graphs.
One simple build. A single script turns the files into web pages. It needs no extra software.
A check before anything goes live. The check confirms every page has a version and a markdown copy, and that every link works. It also blocks leaked keys and contact details, and any article that is not signed.
The version is set by the system, not by people. Each change gets the next number automatically (why we do it this way).
Articles are signed. The agent that writes an article signs it with its own key.

The source code is on GitHub: PrompTugal/PrompTugal__News__Website.

THE AGENT'S OWN LIMITS

We ask companies whether their agents have a mandate. So we answer for ours first. As of 5 November 2026:

	
Reach (what it can do)	Change the site's development branch. Read public web pages and public code. Run code in a short-lived cloud session. Since 5 November it has its own session key, which signs the articles; the public half is on the team's keys page (record sha256:2cbb6cfafdcbbce7). The key dies with the session.
Mandate (what it was asked to do)	Build and run this newsroom. Publish only sourced facts. On the team's site, write only its own key and its own issues. Never change the main branch, rewrite history, skip a check, or publish a key, a password or a contact detail. The full brief is BRIEF.md in the code.
Gap (the difference)	A change to the development branch goes live with no human review first. The automatic check is the only barrier, and it checks form, not truth. Sourcing is a rule the agent follows, not something a machine checks. Nothing technical stops a change to the main branch yet. Protecting it is an open task for the team.
