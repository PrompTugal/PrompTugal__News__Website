ITS FLOWS, AND WHERE AI AGENTS ARE IN THEM

How work moves through 1Password's product, as its public pages describe it, and the steps where an AI agent acts (4 steps with an agent, marked Agent). Each step cites its source.

A personal agent signs in to a website (1Password for Agents)

For an individual or family account: a person delegates a task that needs a sign-in, such as booking a flight, and 1Password fills the login in the agent's browser instead of the person sharing the password with the agent. Opt-in, for supported agent apps. (support.1password.com/1password-for-agents/, read 2026-11-06)

The person: Connects 1Password to a supported agent app. Connecting lets the agent ask 1Password to sign in; it does not give the agent access to the person's vaults. (support.1password.com/1password-for-agents/, read 2026-11-06)
The agent: Reaches a step of its task that needs a sign-in and asks 1Password to sign in. Agent: Carries out the delegated task (for example booking a flight or shopping for groceries) and asks 1Password for a sign-in when it needs one. (support.1password.com/1password-for-agents/, read 2026-11-06)
1Password: Shows the person which agent is asking to sign in, with suggested logins for the website. (support.1password.com/1password-for-agents/, read 2026-11-06)
The person: Reviews the request and chooses whether to approve it. (support.1password.com/1password-for-agents/, read 2026-11-06)
1Password: Fills the username, password and one-time password directly into the website's sign-in form in the agent's browser; the agent app makes sure the agent cannot see the sign-in page. (support.1password.com/1password-for-agents/, read 2026-11-06)
The agent: Continues the task, signed in. The person can disconnect the integration at any time. Agent: Completes the task without the credentials entering its chat. (support.1password.com/1password-for-agents/, read 2026-11-06)
An AI agent in a browser gets a credential (Secure Agentic Autofill, with Browserbase)

1Password's first implementation for browser-use agents, through Browserbase: credentials are injected into the agent's browser by the 1Password browser extension only when required and always authorised by a person, so the agent and the underlying model never see them. (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)

The person: Sets it up: 1Password shows a prompt that details what the agentic browser will be able to request from 1Password; Browserbase cannot access, see or modify anything in a vault without approval. (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)
The agent: Runs a workflow in the browser and, when it needs to sign in, informs 1Password that a credential is being requested. Agent: Executes the browser workflow and requests a credential from 1Password instead of receiving one in its prompt. (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)
1Password: Identifies the appropriate credentials and asks the person for approval; where a site has more than one login, the person chooses which to use. (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)
The person: Approves or refuses in real time; every credential request needs a person's approval by default. (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)
1Password: If, and only if, the person approves, injects the credential into the browser over an end-to-end encrypted channel (a protocol built on the Noise Framework) between the approving 1Password device and the extension in the remote browser, just in time. (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)
The agent: Carries on with the workflow, signed in; the credential never enters the model's context. Agent: Completes the workflow with access limited to the credentials that workflow needs (least privilege). (1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-, read 2026-11-06)
