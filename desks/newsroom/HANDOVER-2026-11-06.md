## 2. How it is built

- **Build** (`admin/build/build.mjs` + `lib/` + `features/`): a small core; each section is a feature module auto-loaded from `features/` in `order`. The contract (full in `admin/build/README.md`): `pages(ctx)`, `fill` (markdown markers `<!-- name -->`), `assets {css, js}`, `api(ctx)`, `searchDocs(ctx)`, `llms(ctx)`, `validate(gate)`, `decorate`. The core gives every page its shell, markdown twin, version badge, agent block, llms.txt line and sitemap entry, plus `page-type` and `page-date` meta tags (the meter prices by them). Nav, footer, utility links and llms groups: `data/site/nav.json`; shell words and the name: `data/site/site.json` (one place). A new feature needs its file, its `assets/<feature>/`, and at most one nav line.
- **Layout hooks** for features without HTML: `::: class` / `:::` blocks and `{.class}` on the next block (`lib/markdown.mjs`); `slotLine`/`slotList` for agenda lines (`lib/present.mjs`). Twins stay plain text.
- **Gate** (`admin/build/validate.js`, 13 checks): builds once and fails if the build changes a tracked file; versions, links, canonicals, twins, agent blocks, key-leak tripwire, no contact details in `content/`, `data/`, `desks/`; signed articles and titles under 12 words; div balance and no em-dashes; the estate's files; every data file against its schema and every reference resolving, derived files fresh (check 11); each feature's own checks (12); page meta (13).
- **Data** (`data/`, see `data/README.md`): hand-edited `companies/<id>/` (company, sources, facts, edges, recheck), `places/`, `topics/`, `curation/`, `ontology.json` (13 types, 20 verbs each with an inverse, forbidden vague verbs), 24+ schemas; derived and committed by `node admin/tools/derive.mjs` from `desks/`: `events/` (official vs other, `our_pick`), `people/` (public, professional, as the summit lists them; no social handles, the gate refuses them), `organisations/`, `evidence/`, `stories/`, `matching.json` (every speaker organisation matched or not, with `same_as`/`not_same` decisions). `admin/tools/companies.mjs` rebuilds companies from the team's map, public fields only (the team's notes never).
- **Graphs and API** (`/api/v1/`, built, never committed): every entity as JSON, indexes, one graph per company, event and person, `industry`, `summit`, `people`, `whole` (every view a subgraph of the whole: the fractal claim), `whole.cytoscape.json`, `triples.nt`, `explorer.json` (compact, with PageRank, betweenness, degree and map positions), `manifest.json` (sha256 per file).

## 3. The interactive features

- **Search** (`features/search.mjs`, `assets/search/search-core.js` shared by build and browser): `api/v1/search/docs.json` (about 39 KB gzipped) plus term shards by two-letter prefix; accent folding, light stemming, prefix matching, synonyms from the data; a query loads 1 to 3 shards (under 7 KB). `/` focuses the top-bar search; `/search/?q=` with facets. I changed the ranking on 5 November so a title that starts with what is typed ranks first ("rep" gives Replit) and widened prefix candidates to 80.
- **The page tool API** (`assets/core/tool-api.js`): `window.__tool` with `register`, `list`, `call(name, args, {levels})`, `log`, `schemas`. Features register through a queue that works in any load order: `(window.__toolQueue = window.__toolQueue || []).push(['register', name, {level, description, params, run}])`. Levels: read, view, author (author unused, off). Model-facing names replace dots with `__` (`graph__focus`). 23 tools on a company page: search, get_entity, list_entities, now, agenda, neighbours, get_page (read); open, highlight (view); 14 `graph.*`.
- **Ask the newsroom** (`assets/chat/`): right-hand pane in `#nr-pane`; the reader's own OpenRouter key in localStorage, sent only to openrouter.ai; default model `anthropic/claude-sonnet-5` (graphs.sgit.ai's); every tool call shown; a tool console works without a key. Ported from graphs.sgit.ai's `assets/universe-chat/`. **No real model has answered yet**: the tests mock OpenRouter. Dinis needs to add a key (Ask, Settings) and try "what is happening today?".
- **The graph explorer** (`/graph/`, `assets/graph/`, Cytoscape.js 3.30.2 vendored byte for byte with its licence; engine pieces ported from graphs.sgit.ai, Apache-2.0, credited): anchors, top N by PageRank/betweenness/degree, edge bridges, filters by world/type/verb/facet, layouts (force, map, radial, layered, tree, grid, list), paths between two nodes read as sentences, shareable URL state (`view`, `focus`, `depth`, `anchors`, `path=a~b`, `top`, `layout`, ...). Mini-graphs are prerendered SVG on entity pages. The chat drives it: tested 5 November, `graph.focus` through `window.__tool` on `/graph/`, `graph.path` answers on any page (note: `max` is the most hops, not the number of paths).
- **Billing** (`features/billing.mjs`, `assets/meter/`, SG Meter vendored at an immutable path): newsroom.sgit.ai's model: £5.00 starting credit per browser, pence per page by type and freshness times share read, never blocking, rate and decline. Prices: `data/billing/prices.json` (one file makes the meter's config and the published billing page; the gate checks they agree).
- **Account and vault** (`features/account.mjs`, `assets/vault/`, sg-vault v0.2.3 vendored, server `https://dev.send.sgraph.ai`): `/account/`, top-up, topped-up, and the vault pane (passkey, create with an access key, update, recovery code, open on another device). Hook for features: `window.__vault.save(path, json)`, `load`, `list`, `remove`, `status`, `open`; events `nr-vault-saved`, `nr-vault-status`, `nr-pane-open` (panes take turns). The chat saves each finished turn to `chat/<started>` only when the reader has opened their vault.
- **The control centre** (`/admin/`, to become `/newsroom/`): overview (the status report from data), runs, agents (a page each), timeline (swim lanes by day), data, workflows, lab, release history; `/api/v1/admin/status.json`.
- **The shell's mount points** (every page): `<div class="tools" id="nr-tools">` in the top bar, `<div id="nr-live">` under the nav (filled 9 to 12 November in the browser; `?now=2026-11-10T11:52` simulates), `<div id="nr-pane" hidden>` before the footer. A pane removes `hidden` from `#nr-pane` when it opens and restores it when nothing in it is open (both the chat and the vault do this since 5 November; a new pane must too).
