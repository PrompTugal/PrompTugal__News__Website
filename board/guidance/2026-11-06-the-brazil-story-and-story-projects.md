# The Brazil story, story projects, privacy, contributions

## 1. The article is a wall of text

- "The problem with this story is ... the problem with the current news publishing. It's a massive wall of text where the information is spread across the board ... we're not using the space correctly ... it's not consumable."
- "We have no ads, so the space that in normal websites is competing for the attention of the user ... what we should be having is a whole bunch of materials that leverage the graphs, the facts, the analysis, download the data: here's the JSON file of this."
- "Multiple rounds ... we add a lot of stuff, then we refactor, then we make it easy, then we add more stuff, then we refactor, then we clean up ... easy to understand, easy to see ... but it's kind of there available."
- Modes by reader: "maybe we have a focus mode where everything becomes just the article"; more data for the curious reader; "this graph of this article".
- "The journalist and the [curious] user [need] the same information design, the same architecture, the same graph visualisations ... the journalist also needs to navigate through this ... to find the nugget." (As in the book: https://the-ultimate-insider.book.sgit.ai/.)
- "Telling the story through pictures ... figuring out the formula ... how to do a timeline, how to do these mappings."

## 2. The Brazil story: go deep

- "Which companies? What do they do? What's their intersection? How do they connect?" "Who's organising? What technologies are they using? Where's the link to everything they do?"
- "Mapping everything we know about Brazil in the summit: Brazilian startups, Brazilian founders, Brazilian employees, companies that are already here with Brazilian roots ... a Brazil section that contains everything we know about Brazil in this summit, and then Portugal, and the UK one, and around the world."
- "Maybe the researcher can find out companies who are doing press releases, who are sharing who's coming."
- Every source the article cites: "we should do an analysis of that page ... extract the data ... an article that explains that stuff ... the links and the facts and the materials and the topics ... in JSON format", as newsroom.sgit.ai does with documents.
- "At the end of an article like this: if you're part of this group, let us know, send us information, send a pull request, contact our agents ... the email ... our PKI ... eventually the append lanes."
- After Brazil: Técnico, "the UK crowd", many more.

## 3. Articles as navigable data

- "Every one of these articles needs to have a specific folder in a specific location ... you put the data in there and you process it once and then you consume it."
- "Almost a JSON navigable structure of the content ... even Markdown converted into JSON [as on graphs.sgit.ai] ... everything becomes linkable entities, you can link a block, a section."
- "We're making it cheaper and more efficient to consume data: an agent navigating this information through these JSON files is going to be much more efficient."
- Data can become massive: "gigabytes ... we just need to make sure they are in the right place ... put a vault on it ... archives ... consume data from the vault."

## 4. Privacy first

- "We have to have a really strong privacy policy ... show that we are also privacy first ... there are no cookies, no tracking, no selling of the user ... we almost don't need one ... the only thing we capture from the user is the city and the region, and even that with a caveat. So we need to map that out ... it's super powerful."

## 5. Story projects, budgets, and work others can pick up

- "Which of the stories we're going to focus on ... maybe that's a topic, and then it has a budget, and then we do the research, and then we publish it."
- "We should also be working in collaboration with Vicky's agents, Angelo's agents, Indi's agents ... the other agents can pick up tasks, especially when we start running things on Sonnet and Haiku ... and other accounts [with] journalists, researchers, curators, analysts, correspondents ... we need to have this body of things to delegate."

## 6. The measure of success

- "Our measure of success is how many humans we're able to involve in this ... how many people we get to contribute, and the agents they bring to the table ... the outreach, the Sherpas connect the dots." Tracked separately.
