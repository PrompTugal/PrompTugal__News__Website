# Everything clickable, updates, sub-sites, visibility, signed-in views

## 1. Everything clickable, with modes (semantic graphs, semantic paragraphs)

- "Just about everything should be clickable all the time ... and even there's modes that we should activate ... go back to the work that we've done with semantic graphs, semantic paragraphs."
- On the Brazil article: "I should have a mode that I flick where it's suddenly trade agency and Sebrae and National Startup Mission and Web Summit ... investor ... all of those become hyperlinks ... allow me to go into that graph ... navigate further into that particular topic."
- "A mode for mapping facts, mapping hypotheses, mapping opinions, and mapping all sorts of information that is kind of like the flows."
- "Brazilian delegation, I should be able to click on it ... all these different ways to arrive at the same conversation." "We really need to think about information design ... how to present materials."
- "It has to be clickable, but you have to reflect the audience" (the Sherpa's job).

## 2. A section for the site's updates

- "You almost need a whole new section just to describe the updates that happen on the website ... go to a particular section and see what are the major updates, what has Vicky done, what has [each] done ... in fact you probably need a journalist section just for that."
- "An agent that goes through all the motions, and all the mini agents inside of it in one run, at a regular interval, and then you publish ... in some of these cases we need an hourly update, and this is the power of a journalist: the journalist writes the story, connects the dots, takes the pictures."

## 3. Sections as sub-sites

- "This whole thing is going to be made of multiple sections, which again can have multiple designs ... a common theme, but I'm more than happy for us to really explore multiple designs, like we did with the dashboard."
- "I'm very keen for Silvio [and others] to go to town with these agents and say, now you manage that area ... a lot of publications have sub-sites inside of it ... allow a particular site for a particular topic to have different navigations ... and then we'll experiment."

## 4. Visibility of everything, and every agent's reads

- "We should have now maximum visibility and maximum understanding of everything that happens on the website. Again, double check ... enough append lanes ... visibility on everything that happens on this website."
- "Every agent that reads anything from the website, we need to capture which agent it was, what they read. So we need to have guidance for every one of them, and this should be part of the agent behaviour policy."

## 5. Coverage of skills

- "If you feel that we need specific agents ... a UX expert, do we need that? Do we have enough coverage of these domains? We can start new agents, that's fine."

## 6. Signed-in views: the start of personalisation

- "Use us, including me, as a more power user ... once you detect that I'm logged in ... with a clean signature, I might have other features ... a little flicker to say normal view or Dinis's view ... I want to start to live what this website looks like."
- "Everybody on the team needs the same thing ... the ability to start creating their own version of this ... see what the website looks normally and then what it looks for their view ... the beginning of the super-personalisation angle."
