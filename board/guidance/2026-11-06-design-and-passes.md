## 3. The synthetic readers page

- "This is really cool ... This page is amazing, but it's completely unreadable." The synthetic agent made him an infographic view of it, "and it actually becomes very well".
- "Who actually has read this?" Findings need a follow-up workflow: "synthetic readers did something, then a bunch of agents should take a look at it ... review it ... map it ... decide what to do with it ... there's a lot of good lessons in here" that must not get lost.
- "There's a graph view of this data of the synthetic readers that is very, very powerful": the historian and the ontologist pick up the key themes and present them.
- Every page should go through several rounds of design: "a designer and a dev to have a loop on this".

## 4. Budgets (the accountant)

- "It's very easy for a synthetic run like this to become an infinite loop ... you pick some stuff, then the dev does some stuff, and then he runs again and he keeps finding it."
- Every run and every loop ("think about the state machine that we follow, if this then that") gets a budget of tokens and runs from the accountant, daily or per piece; "the agent should be hitting the budget and then stopping, and then we understand the side effects".

## 5. Passes: a concept for focused rounds of work

- "We need a concept here, maybe we call projects, or a run ... and we kind of did this in the newsroom [newsroom.sgit.ai] ... always take a look at newsroom.sgit.ai to get best practices from it."
- A pass of quality on a page: "fire up multiple agents, some in parallel, some in sequence": one reviews the usability, one reviews what the page is doing (the ontologist and others), the designer, an agent that represents the user (the Sherpa).
- "Then you plan maybe two or three rounds of work ... designer, then developer implements, then designer, then implements ... maybe with the Sherpa in the middle. And then at the end you reach a state. You map what you've done, you collect everything, and maybe the journalist writes a story about everything, and then you wrap it all up."
- "Always the conductor runs first, and the security runs first, and then at the end you have the security running and then the conductor running."

## 6. New agents

- A **DevOps** agent: "focused on the health, quality and performance of our CI pipeline and every script and automation we have on this site".
- An **accountant** agent (he asked the other agent to ask the conductor): budgets of tokens and runs.
- A **Sherpa** agent ("the agent that represents the user"), as on the SG/Send project, whose team had "amazing good definitions".
- A **librarian** agent, as on the SG/Send project, "that maps all this stuff".
- "Some of these agents don't need to run every hour ... they can run slower, but important that they start to do the stuff ... and they map everything."
- The security agent runs first and last in every pass (section 5).
