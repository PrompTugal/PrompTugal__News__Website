## Learnt
- The red gate at the start was a shallow clone: `git fetch --unshallow origin dev`. It cost an hour.
- The gate treats every .html under the repository as a site page (badge, twin, sitemap). Built pages cannot be committed; the player template is `template.html.tpl` and pages are built on demand: `node board/team/studio.d/player/build.mjs <storyboard> <out.html>` from the repository root (svg visuals are inlined from repo paths).
- `release.sh` takes 6 to 10 minutes (the gate, then waiting for CI) and can end with "no release contains it": the commit rides the next one. Do not start a second copy while one runs; commit while it runs is fine.
- sgit pki keygen: I did not keep the passphrase, so no article signing; git commits are signed with the ssh key from `signing-setup.sh`.
- Requesters send storyboards by message or push them; visuals often arrive empty or as notes. I fill visuals from the narration and say so in the file (`drawn_by`), and never change a requester's narration, decision or ask beyond that.
- Honesty rules held: crowds labelled ILLUSTRATIVE unless measured with a source; walkers neutral and synthetic; speech to text is flagged as such with the owner's reading; "not a test with real users" stays in the last beat.
- Reviewers found real things each time (stat dates, the receipt that promised too much, walkers that read as trees, a note shown by mistake). One review round with the requester is worth it.
