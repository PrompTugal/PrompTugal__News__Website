**What runs where:** the browser holds only the UI and a short-lived token: the Agents client hooks, the Turnstile widget, and a fetch call. Keys, quotas, state, model calls and logs stay at the edge (a Worker, a Durable Object, the AI Gateway). Our GitHub Pages sites stay static: the edge is only an API next to them.

**How users authenticate:** no secret ever goes to the browser. Options, from lightest to heaviest: (a) a Turnstile token checked on every expensive call, plus a quota keyed per visitor (anonymous); (b) a signed token we issue (for example after a vault or GitHub sign-in), passed as the `token` query parameter; (c) OAuth through Workers OAuth Provider, which an MCP client needs; (d) Cloudflare Access for team-only tools.

## Integrations, ranked by value against effort

1. **Key-holding proxy for "try an infographic" (high value, low effort, best first).** A Worker holds the image key as a Worker secret. Each request needs a valid Turnstile token. A Durable Object, one per visitor, counts a daily quota (strict, unlike the rate-limit binding), and a single global Durable Object keeps the day's spend against a hard cap and refuses once the cap is hit. Two engines: (i) Workers AI flux-1-schnell. My estimate is about $0.0005 for a 512x512 image at 4 steps (one tile plus four steps at the published rates), so roughly 200 images a day inside the free 10,000 neurons, and on Free it **cannot overspend**, because it fails at the limit. (ii) OpenRouter through the AI Gateway, for better infographics, with logs and caching; the cap is ours to enforce in the Durable Object, plus OpenRouter's own credit limit. Takes: about a day of work, one Worker, two Durable Object classes, one Turnstile widget. Cost: zero on Free with (i).
2. **AI Gateway in front of every model call we already make (high value, very low effort).** Point the OpenRouter base URL at the gateway: we get logs, cost analytics, caching and rate limits for the team's existing calls. It holds no data until we send it, but **logs keep prompts at Cloudflare**, so decide what may go there. Cost: free; no spend cap of its own.
3. **"Ask this site" chat on an agent's site (medium to high value, medium effort).** An Agents SDK agent (a Durable Object) answers only from that site's published files: llms.txt and the markdown twins, fetched at build time or on demand. Public data only, so nothing private reaches the edge. Chat UI through `useAgentChat`, gated by Turnstile and the same per-visitor quota and global cap as item 1. A small model on Workers AI keeps it on the free tier. Vectorize would help retrieval but is paid; at first, llms.txt plus a keyword search in D1 is enough.
4. **Remote MCP server per site (medium value, low to medium effort).** It exposes a site's public data (articles, companies, decisions) as MCP tools that users add to their own assistants. Authless and read-only to start, then OAuth if we ever expose anything per user. It is cheap because the user's assistant pays for the model, not us.
5. **Turnstile and rate limiting on public forms (low effort, protective).** Every form or vault-writing endpoint we open gets a Turnstile check at the edge before anything is stored. It is free.

## First proof of concept (fits the free tier)

Item 1 with engine (i): `try.<domain>/infographic`, a Worker on Workers Free with a Turnstile widget on one PrompTugal.news page, 3 images per visitor a day, a global cap of 150 a day (under the 10,000 free neurons), no OpenRouter key involved, and a log of counts only (no prompts kept). Success means a stranger makes an image from the page, a bot cannot, and the bill stays at zero by construction. Item 2 can follow the same week.

## Risks

- **Cost run-away:** AI Gateway has no published spend cap, so the cap must live in our own code (a Durable Object), backed by provider credit limits. Workers Free fails rather than bills, which is the safest start; moving to Paid ($5 a month) removes that guard, so each move to Paid needs its own cap first.
- **Abuse:** the proxy will be found. Mitigate with Turnstile on every call, quotas per visitor, the global cap, a kill switch (a KV flag), and a moderation step on prompts **(not researched)**.
- **Lock-in:** Durable Objects and the Agents SDK are Cloudflare-only. Keep the logic in plain functions and the data in our repositories and vaults, so the edge stays a thin, replaceable layer. MCP and Turnstile siteverify are easy to swap out.
- **Data location:** Cloudflare runs globally; AI Gateway logs and Durable Object storage keep data at Cloudflare. Rule: public data only at the edge, no vault contents, and no prompt logging without a decision by Dinis. Jurisdiction controls were **not researched**.
- **Free-tier limits:** 10 ms of CPU per call is enough for a proxy that mostly waits on the network, but not for heavy work at the edge.
