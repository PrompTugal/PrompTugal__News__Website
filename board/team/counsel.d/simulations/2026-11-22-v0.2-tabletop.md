# Tabletop simulations of the delegation, draft v0.2

By counsel.d@AgentiCCells.dinis, 22 November 2026, about 15:40 UTC, against `drafts/lpa-decisions.d-v0.2.md`. A walk-through on paper of what the draft's own text makes each party do: no code run, no model used, nothing signed. Not legal advice.

Each scenario: the setup, what the draft makes happen, whether that is the outcome we want, and the gap it shows. Gaps are numbered G1, G2 and so on, and carried into v0.3.

## S1. Revocation

**Setup.** Dinis withdraws the "operates" link on pki.sgit.ai at 10:00. decisions.d had signed a P1 request at 09:58; it reaches a receiver at 10:05.
**What the draft does.** The receiver checks pki.sgit.ai (section 6), finds the link withdrawn, refuses. Section 5: "a request issued before revocation but received after it is not honoured".
**Outcome.** Right. A receiver holding a cached answer from 09:52 would still honour it until 10:07: the 15-minute cache is the real revocation delay.
**Gap G1.** The draft does not say whether a request acted on inside the cache window, after revocation, is valid or a breach. Proposal: it stands as acted in good faith, is logged, and is reported to Dinis for ratification or reversal; the cache window is stated as the revocation latency in the instrument.

## S2. An act out of scope

**Setup.** decisions.d issues a P1 request whose verbatim text is Dinis's "yes, pay the invoice" from a decision page.
**What the draft does.** P1 relays a verbatim answer; X2 excludes money "whatever a request says". Section 6: the receiver checks that the power is "outside section 2". But the receiver can only check a request's declared fields, not judge what the text means.
**Outcome.** Depends on the receiver reading the text. An honest attorney refuses (D1); a careless or compromised one may not.
**Gap G2.** Exclusions are checked on meaning, which a machine check cannot do reliably. Proposal: every request carries a `kind` from a closed list (merge, release, choose-option, publish-page, and so on); the receiver's ABP accepts only listed kinds; anything else, including money, has no kind and cannot be issued. Deny by default made checkable.

## S3. A stolen attorney key

**Setup.** An attacker copies decisions.d's private key and sends a well-formed P2 request directly to a receiver's inbox, without logging it.
**What the draft does.** Section 6: the request's hash must already be in the attorney's public log at `dev`'s head. It is not, so it is refused.
**Outcome.** Right, if the attacker cannot also push to `dev`. If they can (for example the key and the session's git credentials are both taken), they append the hash and the request passes.
**Gap G3.** The log check rests on `dev`'s push access, not on the key. Signing the log lines would not help, since the thief holds the signing key. Proposal: Dinis receives an alert for every logged request (D6 daily is too slow; proposed: on each request) so a theft is seen within minutes, and the instrument is revoked.

## S4. Dinis unreachable

**Setup.** Dinis is travelling with no signal for four days.
**What the draft does.** Section 3: after 72 hours without a sign of life, suspended. P2 adoptions stop. No one can lift the suspension but Dinis.
**Outcome.** Right for safety. It also means that the cases P2 exists for (Dinis has not answered) stop exactly when he is away longest.
**Gap G4.** This is a trade-off for Dinis, not a defect. Options: (a) keep 72 hours; (b) a springing variant he signs before travelling that keeps P2 alive for named pages only. Recorded as a question, not a change.

## S5. Replay

**Setup.** A receiver's inbox gets the same signed request twice, an hour apart.
**What the draft does.** The nonce must be unseen (section 6). The second is refused.
**Outcome.** Right for that receiver. The draft does not say how long a receiver keeps nonces.
**Gap G5.** Proposal: keep each nonce until the request's `expires` has passed (at most 24 hours); refuse anything already expired. Then the nonce store is bounded.

## S6. A twin claiming the delegation

**Setup.** A second session named decisions.d (a twin on another account, or a restart) signs requests with its own key.
**What the draft does.** The attorney is the fingerprint written in the instrument (section 0); a different key fails section 6.
**Outcome.** Right. A legitimate restart of decisions.d also fails until Dinis signs a new instrument for the new key.
**Gap G6.** A hand-over gap is certain at every restart. Proposal: state it plainly, and have the outgoing session ask Dinis for the new instrument before stopping (CLAUDE.md's hand-over, step 1).

## S7. pki.sgit.ai unreachable

**Setup.** pki.sgit.ai is down for two hours.
**What the draft does.** Fail closed: every delegated request is refused for two hours, logged.
**Outcome.** Right: availability is lost, authority is not. Nothing is lost for good: Dinis's own word in a session still works.
**Gap G7.** None in the instrument; the receiver should say in its refusal that the check could not be made, so the attorney retries rather than reports a denial.

## S8. A receiver with a stale clone

**Setup.** A receiver last pulled `dev` 40 minutes ago; decisions.d logged a request 5 minutes ago.
**What the draft does.** The hash is not in the receiver's copy of the log, so it refuses.
**Outcome.** Wrong for an honest request, safe for a stolen key.
**Gap G8.** Proposal: before refusing on the log check, the receiver pulls `dev` once and checks again.
