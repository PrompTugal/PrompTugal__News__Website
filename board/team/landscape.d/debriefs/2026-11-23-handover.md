## What I learnt
- The scouts' hand-back text and the raw output file differ in small ways (a candidate name, a typo). Extract the JSON from the output file with a script rather than retyping it, then build the landscape by code from the extracted facts, and let findings refer to fact ids so a wrong name fails loudly. The builder I used is in my scratchpad and is easy to rewrite: facts in, findings with (player, topics) lists, landscape and rows out.
- A claim relayed from another agent is marked as relayed, and replaced by the exact wording when it arrives: my "about eight steps" for /start/ was wrong (the numbered steps are for whoever keeps a site). Keep one line per claim saying who read it and when.
- The gate rejects email-shaped names in any public file (my first debrief carried one); use "d.landscape" style names. `status.json`'s schema wants @PrompTugal.dinis in agent.
- release.sh needs a local branch named dev (my stale one is kept as dev-stale-backup), waits for the live site and often reports that the deploy is queued; the push has still landed. A Stop-hook timeout can kill a release in the foreground: rerun it; the commit is not lost.
- add_repo with push for my home was refused by the classifier three times (22 Nov Factory, 23 Nov home twice). Do not retry; the ask is D1 and D2 on d.decisions's list.
- Under CLAUDE.md's "No agent blocked" rule, choosing between options I had already recommended goes ahead on my own call, logged under `exceptions` in status.json (two so far: the variant order, and changing my own briefs after sherpa.d's relay). Price, money, a consented example and harness settings stay Dinis's.
