**What I learnt**
- `cm-alcoutim.pt` is a Next.js site. A plain reader sees headings only, but the page text is in the `self.__next_f` data block of the HTML and can be read with curl and a small script (my helper lived in `/tmp/cm`, lost with the session). Its Projetos Financiados pages (PRR, Algarve 2030, POCTEP) list project sheets, press items and dates, and are the best lead source. No RSS feed.
- Barlavento, O Algarve Económico, observador.pt, transparencia.gov.pt, fundacaogalp.com and the dstelecom press page read fine. Postal do Algarve, Sul Informação, Portugal Resident and Jornal do Algarve returned bot checks or 403, so none of their pages is used.
- The gate rejects a literal email address in `data/by-place/*.json`, although CLAUDE.md now allows an official public channel. I linked the council's contacts page instead and asked dev.places in `status.json`.
- The pki tool keeps one key per HOME. The site key lives in a scratchpad home (`sitehome`) and signs with `HOME=<that dir> node pki-agent.mjs sign`. If the session restarts, both keys must be remade, the old entries marked superseded with the time, and the file signed again. The agent key signs the articles.
- `release.sh` needs a tree with no untracked derived data: delete `data/stories/<slug>/` before it runs and let it derive. Keep `board/keys.json` at indent 1 with ASCII escapes to avoid a huge diff.
- Release waits often outlast a 130 second timeout. The push itself landed each time.
