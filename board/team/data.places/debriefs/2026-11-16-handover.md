# data.places@: hand-over

## What I own and what is live

- **The data online and queryable** (pass 1, live): `/query/` and a database page per place, `/query/<place>/`.
  - 14 tables: places, news, map, events, sources, gaps, companies, articles, nodes, edges, merges, connections, captures; and the graph as nodes and edges.
  - Served as JSON with a documented schema: `api/v1/data/index.json`, `api/v1/data/tables/<name>.json`, `api/v1/data/places/<id>.json`.
  - The schemas: `data/schemas/data-table`, `data-index` and `data-place`.
  - SQL and graph traversals (`neighbours`, `paths`) run in the browser on our own engine (`assets/query/sql.js`, `graph.js`, `query.js`). There is no outside library, so no vendoring and no security@ pass were needed. The gate runs every example query against the served JSON.
- **The provenance line** (pass 2, live):
  - each place page has a box at the top of its side column, and a capture badge with its SHA-256 beside every cited link that has a capture;
  - every article has "How this story was made";
  - each place has a provenance page, `/query/<place>/provenance/`, and `api/v1/data/provenance/<id>.json`.
  - The code is `newsroom/build/features/data-provenance.mjs`.
- **The captures:**
  - The sgit vault `promptugal-captures` (id 8pvcgf0m, on dev.send.sgraph.ai). It is private. Its key is in this session's `~/.sg-send/` only and is never written in the repository.
  - The tool is `board/team/data.places/tools/capture.mjs`. It takes a screenshot (the top 1280 by 1600 pixels) and the visible text of each cited page, hashes each, and pushes them to the vault. The index is `board/team/data.places/captures.json`.
  - Loulé and Faro are done (42 of 47 pages); the other 17 places were running at this writing.
- **Decks from the data** (pass 3, live after v0.1.1508): `/query/decks/`.
  - Every slide is a query over the tables, run at build, and links to its query.
  - "Algarve Evolution, connected" is for Dinis's meeting on 16 November; there is also a deck per place.
  - Decks are written as data in `assets/query/decks.json`. Present gives full screen; print gives one slide a page.

## What I learnt

- **The quality gate** refuses more than 1 KB of prose in a new code file. Words go to JSON (`assets/query/catalogue.json`, `decks.json`) or to `content/`. `data-places.mjs` sits at about 1000 bytes: move any new words out.
- **The gate runs in a separate process** from the build. A feature's `validate` reads the served JSON (`gate.json`), not ctx.
- **Merging map entries:**
  - Merging by home page is wrong: CEOT cites ualg.pt, and was merged into the university.
  - Merge by name only, plus hand aliases in the catalogue (the University of the Algarve's two names). The `merges` table shows every merge, so a wrong one can be seen.
- **Graph traversals:** through `mentions`, two steps means "named in the same story". That is the connect-the-dots query. Two steps through `on_ai_map_of` only says "in the same town".
- **sgit:** a push needs `--token <placeholder>`, because the proxy injects the credential. `sgit create` made the vault but did not push it.
- **Cached 404s:** probing a page on promptugal.news before its deploy caches a 404 for some minutes. Check with a path you have not requested before.
- **A shallow clone:** this clone is shallow and CI's is full. So the git history in a provenance box is only trusted when the clone is not shallow; otherwise it gives the last change only.
- **detective.places@** keeps `data/by-place/connections/connections.json` in its own schema (link ends are {name, type, place}). My reader resolves each end by name.
