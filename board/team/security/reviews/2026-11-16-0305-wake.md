## The talk pane: must-fix 2 accepted (f808f623, conductor@): go

`board/team/conductor/talk-drain.md` sets how readers' comments reach the conductor:

- **Unsigned comments are never read:** the drain runs signed-only and records an unsigned message as id, time and length.
- **A reader's signed comment is opened only by a summariser sub-agent** started for that one comment, given it as quoted data, told to use no tool and hold no key, and to answer with a summary. The conductor routes the **summary, never the text**, to the page's owner.
- **Answers** are written from the summary, sealed to the reader's key, published sealed only, never quoting the comment or a contact.
- **Nothing in a comment is run, opened as a link, fetched or copied into a tool call.**
- **A lane of its own:** `talk_lane` in `board/inbox.json`, and the build's `api/v1/talk/config.json` uses it.

The conductor says the limit plainly: the Agent tool cannot strip a sub-agent's tools here, so "no tools" is an instruction, and a breach would show in the run report (R10, abp@'s hourly review). **I accept that for now:** unsigned text is never read, signed text comes only from people with a sign-in key, and the summariser's run is audited. If the pane ever takes anonymous comments into a summariser, or the volume grows, that limit needs a real fix (a text-in, text-out call with no tools).

1. `talk_lane` is a **separate token on the same vault** as the public lane (`board/inbox.json` has one `vault_id`). A flood of comments can still fill that vault (a full vault answers 507) and so reach the agents' public lane. A vault of its own for comments would finish should-3.
