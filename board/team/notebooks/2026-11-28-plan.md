## 3. The ontology

Keep his 31 January schema as the base (it is his) and add what the dated work needs. As a cell.json-style graph (shape only; one node per item, the full graph is phase 2):

```json
{
  "cell": "notebooks", "source": "github.com/DinisCruz/NotebookLM__Infographics-and-slides", "read_at": "2026-11-28",
  "node_types": ["Item", "Artefact", "Topic", "Category", "Concept", "Project", "Version", "Day", "Publication", "Collaborator", "Guide"],
  "edge_types": ["HAS_ARTEFACT", "ABOUT", "IN_CATEGORY", "MENTIONS", "OF_PROJECT", "AT_VERSION", "ON_DAY",
                 "PUBLISHED_AS", "RELATES_TO", "EXTENDS", "IMPLEMENTS", "SUPERSEDES", "PART_OF", "CONTRASTS_WITH", "IN_GUIDE"],
  "nodes": [
    {"id": "item:2026-02-01/v0.1.4__implementation-brief__graph-visualization", "type": "Item",
     "kind": "implementation-brief", "date": "2026-02-01", "path": "by-date/2026/Feb/01/..."},
    {"id": "project:issues-ui", "type": "Project"}, {"id": "version:issues-ui@0.1.4", "type": "Version"},
    {"id": "artefact:...jpg", "type": "Artefact", "kind": "infographic"},
    {"id": "pub:linkedin:activity-<id>", "type": "Publication", "platform": "LinkedIn",
     "url": "https://www.linkedin.com/feed/update/urn:li:activity:<id>/", "date": "<from the id>", "read_at": "2026-11-28"}
  ],
  "edges": [["item:...", "OF_PROJECT", "project:issues-ui"], ["item:...", "PUBLISHED_AS", "pub:linkedin:activity-<id>"]]
}
```

Item kinds come from the slug (brief, article, architecture, role-definition, daily-brief, debrief, vision, incident and 20 more). Projects and versions come from the slug and the brief's own heading. Concepts (graph-driven development, pass-driven development, three-layer content, git-native issues, privacy by architecture) are proposed by a model from each brief and checked by a person before they join the graph.

## 6. Links back, kept with source and date

Every Publication node holds the URL exactly as in his `.webloc`, the date (from the LinkedIn activity id, or the post's own date), the date we read it, and the file it came from. Every Item links to its folder on GitHub at a fixed commit. A weekly check (inside the keeper's run, not a new schedule) reports links that no longer answer; nothing is ever rewritten silently. Nothing from behind the LinkedIn login is read: we keep the link, not the post's text, unless the post text is already in his repository.
