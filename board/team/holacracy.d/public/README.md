## In one paragraph
Holacracy runs an organisation on roles, not people: each role has a purpose, domains (what it alone controls) and accountabilities (what it is expected to do), grouped in circles, all written down and changed by a set process. Dinis's agents already work this way in files: a role description, a written grant of what each agent may change, a conductor for each project. What was missing was one record that holds it together, and someone to keep it. holacracy.d is that agent. It keeps the record and writes proposals. It changes nothing itself: only Dinis ratifies.

## Where the live data is
The record is `board/team/holacracy.d/org-chart.json` in the PrompTugal.news repository, drawn to `org-chart.md`; open proposals are in `proposals/`, decisions in `decisions/`. These documents move to the role's own home once it exists.
