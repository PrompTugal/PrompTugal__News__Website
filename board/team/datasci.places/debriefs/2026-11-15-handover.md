## What I learnt
- The build writes pages before the API, and runs `final` after the API: the audit and the spec live in `openapi.mjs`'s `final`, which sees `ctx.api`. Files other features make in `final` (sw.js, deploy-exclude.txt) are listed by hand in FINALS.
- The quality gate (`features/quality.mjs`) refuses prose and HTML tags in code strings above a baseline; vendored code is skipped only under a `vendor/` folder. Words go in a JSON file.
- `piece-flows` needs git history: a shallow clone fails the gate. `git fetch --unshallow origin dev` first.
- Page links and JSON differ in small ways: trailing slashes, http vs https, commit links shortened to nine digits, URLs inside prose. The audit folds these (see `norm` and `urlsIn`).
- Reusing by-place's own `api()` records keeps the page and my endpoints identical; never re-implement another feature's cleaning.
