# promptugal.com and promptugal.ai

## Where they are (read 12:30 UTC, public DNS over https://dns.google)

| Domain | Nameservers | A record | What a visitor gets |
|---|---|---|---|
| promptugal.news | AWS Route 53 (ns-250.awsdns-31.com and three more) | GitHub Pages (185.199.108.153 to .111.153) | the site; www redirects to it (301) |
| promptugal.com | Network Solutions (ns15, ns16.worldnic.com) | 208.91.197.27 (the registrar's parking address) | not the site |
| promptugal.ai | Network Solutions (ns17, ns18.worldnic.com) | 208.91.197.27 | not the site |

So the ledger's PB-15 ("all domains point to promptugal.news for now", decided) is not done. It cannot be done from this repository: GitHub Pages serves one custom domain per repository (`CNAME`: promptugal.news), and the DNS of .com and .ai is in Dinis's registrar account, which no agent holds.

## The options

| | What Dinis does | What a visitor gets | HTTPS on .com and .ai | Effort | Keeps .ai free for later (PB-16) |
|---|---|---|---|---|---|
| **A. Registrar forwarding** (recommended for now) | In Network Solutions, turn on URL forwarding for both domains (and www) to `https://promptugal.news`, as a permanent (301) redirect | promptugal.com/any/path goes to promptugal.news (path kept, if the registrar's forwarding keeps it; to check) | only if the registrar's forwarding serves HTTPS; many do not, and `https://promptugal.com` then fails while `http://` works | about 10 minutes | yes: switch the forwarding off later |
| **B. Route 53 and a redirect bucket** | Move both domains' nameservers to Route 53 (as .news already is), then an S3 bucket set to redirect all requests to promptugal.news, behind CloudFront with an ACM certificate per domain | a 301 on http and https, path kept | yes | about an hour, and a few cents a month | yes: point .ai elsewhere later |
| **C. A second GitHub Pages site** | A new, tiny repository whose Pages site has `CNAME` promptugal.com and a page that redirects (meta refresh and a canonical link), and the DNS for .com at GitHub Pages; the same again for .ai | a redirect after the page loads (not a 301; search engines treat it less well) | yes (GitHub's certificate) | about 30 minutes each, plus a repository each to keep | yes |

**My recommendation:** A now, at Dinis's word "for now"; if `https://promptugal.com` fails under A, then B, which is the lasting form and matches where .news already lives. C only if Dinis would rather not touch AWS. Nothing in this repository changes under A or B.

**After Dinis's answer:** devops@ checks each domain from outside (http and https, the apex and www, a deep path) and records the result in `REALITY.md`'s domains line (through conductor@, who keeps it).
