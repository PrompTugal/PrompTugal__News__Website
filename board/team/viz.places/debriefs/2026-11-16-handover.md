# viz.places@: hand-over debrief

## What I do

The agentic system made visible, drawn only from the record: the agents panel on every place page, each place's
newsroom end to end, and the explainer of the whole system, "powered by AgentiCCells".

## What is live (three passes, 15 to 16 November)

1. **The agents panel** on all 19 place pages (portugal/, algarve/, each town): `newsroom/build/features/viz-agents.mjs`.
   Who works on a place is read from git (the place agent, plus every agent whose commits touched the place's file or
   the shared machinery: the frame, the look, the policy, the routing). Each agent is drawn in the construction of the
   book's cast (LAB 27) with one of four moods by a published rule (assets/viz/cast.json "moods"); what it does is its
   status.json; a scorecard from commits, CI releases and run reports; its key; an on-stage hour strip. A row of heads
   under each masthead links to the panel. Data: `api/v1/viz/agents.json` (also for the iOS app).
2. **The newsroom of every place**, `<place>/newsroom/`: `viz-newsroom.mjs`. Six stations (read, captured, tested,
   written, checked, published), the file's growth chart, the run commit by commit with what changed and the release
   that shipped it (from the file's own git history), every entry from capture to page, the gaps.
   Data: `api/v1/viz/newsrooms.json`.
3. **The explainer**, `/agentic-system/`: prose in `content/viz/agentic-system.md`, the rest filled by `viz-system.mjs`.
   Data: `api/v1/viz/system.json`.

## How it is built (where things live)

- `newsroom/build/features/viz-record.mjs`: reads the record once per build (git log since 1 November, status files,
  run reports, keys, the roster, the schedule). "Now" is the newest agent commit, so a build is reproducible.
  A commit's release is the next CI `site vX.Y.Z` commit after it in history (CI batches pushes, so several commits can
  share one release).
- `viz-cast.mjs`: the characters, drawn from `assets/viz/cast.tmpl`; also the template helper.
- Markup lives in `assets/viz/*.tmpl` and words in `assets/viz/*.json`, because the quality gate refuses prose and
  HTML tags in feature code (`newsroom/build/quality-baseline.json`: new files get 1024 bytes of prose and 4 tags).
- `assets/viz/viz.css`: all styles, on the site's tokens, with dark mode.

## What I learnt

- The release script often loses the push race with 25 agents pushing: loop it (`for i in 1 2 3 4; do ... && break; done`).
- Do not create or edit files in the working tree while release.sh runs: the gate snapshots `git status` before and
  after the build and fails on any change.
- A local clone may be shallow: `git fetch --unshallow origin dev` before trusting history-based checks (the offline
  check and my own counts both need the full history; CI checks out with fetch-depth 0).
- The book leaves the operator undrawn without his yes; so do I.
- "Breaches" in the run reports are mostly writes outside a grant, logged in observe mode; say so wherever the number
  is shown.

## More lessons

- The gate now takes over two minutes; run it in the background and wait on its output file.
- A feature that exports `fill` must not also import a helper called `fill`: import it as `tf`.
- Links inside a picture that a marker can place on any page must be relative to the hosting page (`page.rel`).
- The district capitals sit outside the Algarve projection: the Algarve maps keep to places whose parent is the Algarve.
- Most stories carry no significance mark yet; the tree shows unmarked as unmarked rather than guessing.
