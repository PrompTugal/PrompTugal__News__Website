## What I learnt
- Switches are CSS only: each view is a `::: view view-x` block opened by a heading `{#v-x}`; `.body:has(#v-x:target)` shows it. No script, works offline, and the twin reads as plain text. The default view is shown when nothing is targeted.
- The gate (`node newsroom/build/validate.js`) checks links, orphans, schemas and the quality baseline (prose and HTML tags in code strings). It did not catch an empty fill ("[object Promise]" from an async fill): fills must be synchronous; look at the page.
- Words go in `data/site/list-views.json` (schema `list-views.schema.json`), not in the code; a new data file needs a schema and a KINDS line in `newsroom/build/lib/datacheck.mjs`; the validator does not support `patternProperties` (use `additionalProperties` with a sub-schema).
- A page made in a feature's `pages()` cannot read the articles (they are not loaded yet): use a fill marker.
- Test a date-dependent build by freezing the clock: `node --input-type=module -e "…class extends Date…; await import('./newsroom/build/build.mjs')"`, then rebuild normally.
