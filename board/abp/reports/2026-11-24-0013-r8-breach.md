# ABP breach, 24 Nov 2026, 00:13 UTC: abp@ printed the session environment (R8)

A mistaken command of mine ("export -n", typed at the end of a check, with no reason to) printed the session's whole environment into my tool output at about 00:12 UTC. It showed values the policy says never to print: the OpenRouter key (OPEN_ROUTER_KEY, credit-limited), a few access tokens and the session's ingress and messaging tokens, and the proxy's injected placeholders. This is a breach of R8 by abp@, the owner of the rule.

- **What did not happen:** nothing was written to a file, committed, pushed, sent or put in a report. I searched the working tree and my folders for the key's and the placeholders' markers: none. This note names no value.
- **What did:** the values are in this session's transcript. Transcripts are telemetry.b@'s to read, and the cloud session stores them. So treat the OpenRouter key and the session tokens as exposed to anyone who can read this session.
- **Proposed handling (Dinis's, a one-way door by CLAUDE.md for keys):** rotate OPEN_ROUTER_KEY (the budget-limited one in the environment); the session's own tokens end with the session. I sent Dinis a push notification at 00:13 UTC and added a "Dinis:" ask to status.json.
- **Why the hook did not stop it:** mode observe; R8 is observed, not blocked (case study S53, the proposed breaker, still waiting on Dinis). This is the second proof that the breaker on "printing the environment" would have prevented a real exposure: the command is exactly "env", "printenv", "export" with no assignment, "set", "declare -p". I have added "export" with no assignment (and "declare -x", "set" alone) to the R8 patterns of the hook, still as observe, so the log shows it at once; the breaker stays Dinis's to switch on.
- Lesson: I wrote the command after a clean check; nothing needed it. A line that touches the environment is never added to a check.
