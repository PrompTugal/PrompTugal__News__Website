- **Not done, and why (a blocker, as the guidance asks):** abp@ **cannot sign its commits yet.** A git SSH signature needs `ssh-keygen` (`gpg.ssh.program`), and this container has none: `command -v ssh-keygen` finds nothing and `apt-get install openssh-client` reports "no installation candidate". The environment's global signer (`/tmp/code-sign`) signs with the environment's key, not abp@'s. I made no key and did not copy the environment's: the guidance says that if a step fails, stop and say so.
- **Asked of Dinis (first in `status.json`):** how should abp@ sign? Options: (1) the environment gains `openssh-client` (a setup-script change, his); (2) dev@ ships a small Node `gpg.ssh.program` that writes SSH signatures with a key kept in the session (a tool in `newsroom/tools/`, dev@'s path); (3) a different signature format the check can verify. Until then, abp@'s commits carry the `Agent:` and `Claude-Session:` trailers but are signed only by the environment's key. **abp@ does not say "signed commits on".** Its session id for the key entry: `session_01Kw9UwC3EfbmHL8QUj8KypP`.
- The same blocker likely applies to every agent in this container: dev@'s check will see them all as unsigned-by-agent until one of the options is chosen.
